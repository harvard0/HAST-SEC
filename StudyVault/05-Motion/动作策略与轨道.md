# 动作策略与轨道（核心度 ★★★）

## Purpose

从批准的候选动作中选择与请求和当前姿态适配的动作码，将局部轨道连续地混合到底座运动。策略负责选择，轨道负责时间和叠加。

## Key Files

| 文件 | 职责 |
|---|---|
| `web/v14_generation.mjs` | 装配 v15 底座、技能策略与 bootstrap |
| `motion/base_policy.mjs` | intent、speaking/listening、局部覆盖锁、排队底座变更 |
| `web/v14_base.mjs` | base/idle 网络与待机轨迹选择、审核排除与接续 |
| `web/v13_policy.mjs` | 原有局部动作网络与 text embedding |
| `web/v14_policy.mjs` | 叠加持续周期选择 |
| `web/v15_policy.mjs`、`web/v15_wave.mjs` | expert 与 wave 选择、后备旧策略 |
| `motion/beat_layers.mjs` | mask、插值、包络、冲突轨道淡出 |

## Public Interface

`extendedPolicy(library)` 返回带 `select(entry,history)` 的策略；选择结果包含单个 skill 的 entry、options（如 cycles）和 report。`beatLayers(bones,sources)` 返回 add/sample/active/state/clear/reset。`basePolicy(conditional)` 暴露 attach/apply/lock/sample 及说话、监听等状态接口。

## Internal Flow

```text
canonical key + recent canonical poses
  -> wave handles? -> wave select
  -> expert key?  -> expert select
  -> otherwise   -> original policy + timing select
  -> exactly one skill + cycles
  -> beatLayers.add(mask, source, start/end, parameters)
  -> sample absolute source rotations
  -> envelope weights + per-joint quaternion blend with base
  -> candidate pose -> solver
```

### 轨道参数和时序

| 参数 | 范围 / 语义 |
|---|---|
| speed | 0.4–2，采样时间倍率 |
| strength | 0–1，轨道包络权重 |
| hold | 0–20秒，动作末尾保持 |
| delay | 0–30秒，相对 add 时的轨道时间 |
| cycles | 整数1–4，策略决定的循环次数 |
| tracks | 最多16条；同 mask 冲突触发旧轨道淡出 |

每条轨道要求恰好一个选中 skill 与当前完整骨架参照。来源按固定绝对局部旋转采样，不将上一显示姿态当作下一次累加基线。淡入淡出用五次 ease，fade 至少0.7秒，并随当前/端点最大角距增加；循环还有接缝淡化。

### 底座锁

局部轨道存在时 `behavior.lock()` 锁住原型切换；不会把未覆盖关节缩放成零。覆盖期间收到的底座修改存入 queued，解锁后应用。`clear()` 触发淡出，`reset()` 才立即清除所有轨道和时间。

## Configuration

v15 使用 `/v15-data/` 下 base/idle/expert/wave、codes 与 `configs/v15_review.json` 的待机排除。网络核验 registry、形状、批准来源；新加 key 不能只修改中文提示词。

## Testing

运行 `node tools/check.mjs`。完整环境下记录 key、source、cycles、mask、fade_seconds 与姿态，分别试单侧、双侧、延迟、同侧替换和 release。概率是选择器内部概率，不是动作成功率；需要观察实际角色。
