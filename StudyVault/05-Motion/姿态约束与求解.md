# 姿态约束与求解（核心度 ★★★）

## Purpose

将底座与局部轨道合成的候选姿态变成满足工程约束的连续输出。可行性失败时尝试恢复或保留可行状态，持续保留达到上限则要求暂停。

## Key Files

| 文件 | 职责 |
|---|---|
| `motion/v9/controller.mjs` | 整体 step 与状态提交 |
| `input_target.mjs`、`inertia.mjs` | 输入、质量、历史和惯性目标 |
| `projector.mjs` | 变量、映射、数值扰动、主求解与恢复 |
| `optimizer.mjs`、`numeric_system.mjs` | 残差线性化、阻尼与回溯 |
| `targets.mjs`、`contact.mjs` | 足接触、支撑、倾斜、手部任务 |
| `retained.mjs` | 失败时按已验收状态重新计分 |
| `post_solve.mjs`、`output_smoothing.mjs`、`damped_output.mjs` | 求解后平滑、重新映射和可行性回收 |
| `clock.mjs`、`validate.mjs` | 固定20Hz、显示插值验收 |

未写目录的文件位于 `motion/v9/`；共享 FK、关节范围、历史滤波和动力学位于 `motion/`。

## Public Interface

`controllerV9(controller, options)` 返回 reset、step、rig、validate、write、report。`step(input, dt, options)` 产生 rotations/root/expressions/state/last；`write` 才写入角色。`fixedClock(step, validate, 20, names)` 提供 advance/display/reset/state。

## Internal Flow

```text
inputTarget -> history / quality / regional priors -> projector.prepare
  -> observed FK + realized previous -> contact.propose
  -> projector.solve -> residualSolve
       | feasible -> use candidate
       + infeasible -> restore attempt -> retainedState if necessary
  -> postSolve / outputSmoothing / feasibility recovery
  -> commit or observe contact -> bone/range/feasible audit
  -> face projection + diagnostics
  -> history/aux/previous commit -> result
fixedClock.display -> interpolate -> validate -> interpolated or current
```

## 求解器实际优化什么

目标为多个残差平方和：目标旋转/根位置、接触和支撑任务、惯性、摩擦/拉力/力矩/加速度/jerk 代理。`residualSolve` 线性化残差，计算步长，最多15次回溯寻找有限且下降的代价。约束模式下，当前已可行时新步也必须可行。

> [!important] 代价下降与可行性是两项条件
> `targetsV9` 将足接触偏差、支撑域、身体倾角、手部几何等转成 hard 违反量并独立判定 feasible。最终还检查骨长审计和关节范围，不能只看 final_cost。

## 失败、平滑和状态提交

若主求解不可行，projector 尝试恢复；若仍失败，retainedState 使用上一已验收姿态或初始中立候选，且按当前适用的接触参考重新验收和计分。无可行状态会抛错。失败候选的 attempt 诊断与实际输出分开记录。

平滑会改变姿态，因此 `outputSmoothing` 对候选重新映射并检查约束；失败则搜索向原求解姿态回收的混合比例。最终可行输出进入滤波和历史，避免未显示的候选污染下一帧。

`hold >= maximum_hold_seconds` 时 `requires_pause=true`；主入口检测后暂停。显示层对插值再次 validate，失败返回 current。显示频率可高于求解频率。

## Dependencies

使用 [[动作策略与轨道]] 的候选、[[模型资源与运行时]] 的历史先验、[[角色骨架与旋转]] 的 FK/写入、[[面部表情]] 的独立投影；由 [[页面与对话]] 按固定时钟驱动。

## Configuration

| key | 当前值 | 含义 |
|---|---|---|
| solver_rate | 20 | `checkV9` 强制为20 |
| solve_iterations / restore_iterations | 4 / 8 | 主求解 / 可行恢复预算 |
| support_tolerance_m / contact_tolerance_m | 0.02 / 0.03 | 支撑 / 足接触容差 |
| mass_kg / friction | 60 / 0.65 | 未标定动力学代理 |
| maximum_hold_seconds | 0.5 | 连续保留后暂停阈值 |
| reuse_jacobian | true | 数值导数复用 |
| inertia_body / arms / details | 7 / 4 / 2 | 惯性权重 |
| output_smoothing | 多组 hz/beta/门控参数 | 自适应输出响应，最大频率须低于10Hz |

主入口另设 `arm_collision_enabled=true`、`cached_derivative=true`。工程范围不是人体统计置信区间，动力学代理也未经过真实质量标定。

## Testing

运行 `node tools/check.mjs`；它不证明数值收敛。完整环境下对照 initial/final cost、feasible、bone/range error、contact、held/rejected、平滑回收比例和实际动作。改数值算法需补充针对性数学检查与浏览器长时运行；本库未执行这些运行验收。
