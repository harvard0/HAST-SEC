# 面部表情（核心度 ★★）

## Purpose

将源通道、聊天情绪和手动覆盖合成连续面部权重，再按角色实际可用通道与表情约束投影，减少冲突和突变。

## Key Files

| 文件 | 职责 |
|---|---|
| `face/v9_profile.mjs` | 额外 morph 注册、通道顺序、互斥组 |
| `face/v9_expressions.mjs` | neutral/friendly/happy 等目标姿态 |
| `face/v9_motion.mjs` | 情绪临界阻尼、眨眼包络、口型预算 |
| `face/v9_controller.mjs` | generate → project 装配 |
| `face/feasible_face.mjs`、`face/morph_metric.mjs` | 可用通道、几何度量和表情投影 |
| `face/details.mjs` | 细节 morph 辅助注册 |
| `face/mapping.mjs`、`face/format.mjs` | blendshapes 映射、帧校验与采样辅助 |

## Public Interface

`registerV9Face(vrm)` 返回扩展通道顺序，只对模型实际存在的 morph 注册 expression；`faceControllerV9(...).project(source,dt,quality,options,manual)` 返回最终权重；`faceMotion(order)` 提供 generate/reset/report。

辅助路径 `mapFace(shapes)` 将 blendshapes 转为基础通道，`faceSampler(frames)` 按时间插值。当前主入口使用 v9 控制器，不应把辅助采样器描述为正在实时采集面部。

## Internal Flow

```text
source face channels + manual overrides + playback expression
  -> faceMotion.generate
       emotion targets / damping / blink / lip budget
  -> feasibleFace.project(available, metric, groups)
  -> expressionManager -> VRM
dialogue presentation.expression -> view.faceOptions -> playback options
```

非快速通道采用临界阻尼；口型与眨眼快速通道单独处理。独立眨眼包络会受笑眼/担忧眼抑制；口型总量还受笑嘴等占用预算影响，手动口型先预留。

## Dependencies

依赖 [[角色骨架与旋转]] 加载出的 VRM 和 morph；由 [[姿态约束与求解]] 调用投影，[[页面与对话]] 设置表现选项，源通道来自 [[模型资源与运行时]]。

## Configuration

`configs/v9_control.json` 的 playback_face 默认 enabled=true、expression=friendly、strength=0.5、blinking=true、lip_gain=2。对话会临时修改 expression/strength。`FACE_GROUPS` 限制嘴、眉、眼等组合；角色缺少某 morph 时不强行注册不存在的目标。

> [!tip] 查“为什么不笑”时分层观察
> 先看对话 expression，再看 faceOptions、源/手动权重、available 注册、投影报告和实际 morph。某个 expression 名称被预测出来，不代表导入角色有对应通道。

## Testing

运行 `node tools/check.mjs`。完整环境逐个观察基础表情、眨眼、说话口型、短回复与连续交流；用 `window.languageV13.state()` 查看 face 报告，用角色 audit 看实际权重。自定义角色须重新观察，不由代码语法检查保证视觉一致。
