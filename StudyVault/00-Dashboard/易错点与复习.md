# 易错点与复习

> [!question]- 文件名有 v13，运行的就是 v13 吗？
> `web/v13_lab.mjs` 调用 `web/v14_generation.mjs` 的 `generation()`，返回 `generation: 'v15'`，并装配 `extendedPolicy`。应沿 import 与工厂参数读代码。→ [[系统架构]]、[[页面与对话]]

> [!question]- JSON schema 合格，就等于中文动作理解正确吗？
> schema 限制结构，`compileSlots` 转换字段，`validateResult` 检查可执行范围；语义正确还要将用户要求、结果侧别/部位、选择码和显示动作逐一对照。→ [[中文意图与进程]]、[[中文模型练习]]

> [!question]- 模型返回 unsupported，一定返回错误提示吗？
> 当前 v15 分支会将 unsupported 或无有效动作且不改底座的 command 改成 chat，再调用对话模型。读旧分支的错误文案会误判当前行为。→ [[指令执行链路]]

> [!question]- 计划没有动作 intents，就绝不挥手吗？
> 对话的 `presentation.gesture` 也可以触发问候挥手；`dialogueController.receive()` 会加载并选择该技能。它与 command 的 intents 是两个入口。→ [[页面与对话]]、[[动作策略与轨道]]

> [!question]- 力矩、目标值和资源圆环能当作准确率、真实动力学或显存吗？
> 动力学采用未标定杆段代理，目标值是加权残差；资源接口统计进程 RSS 与部分文件，前端可能加 JS 堆，不包含显存和完整浏览器。→ [[姿态约束与求解]]、[[HTTP接口]]

> [!question]- training 目录说明附带完整训练系统吗？
> 其中有训练数学辅助函数，但当前浏览器直接依赖多个运行时；README 明确未提供完整训练流程和原始视频。模型元数据中的历史训练描述也不是本次重跑结果。→ [[模型资源与运行时]]

> [!question]- 预热页显示“独立显卡”，就证明用了 CUDA 吗？
> `web/v13_latency.mjs` 当前成功提示是固定文案。实际设备需看配置和 `/v13-api/status` 的 runtime.device；还应结合推理进程与实际运行观测。→ [[中文意图与进程]]

> [!question]- 平滑后就一定仍然可行吗？
> 平滑会产生新的候选姿态。`outputSmoothing` 映射并重新验收，必要时向求解结果回收；显示插值也再次验证，失败时显示 current。→ [[姿态约束与求解]]
