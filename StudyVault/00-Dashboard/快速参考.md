# 快速参考

## 命令 → [[安装配置与检查]]

| 目的 | 项目根目录下的命令 |
|---|---|
| 安装 JS 依赖 | `npm ci` |
| 安装 CPU 资源 | `npm run setup` |
| 安装 CUDA 资源 | `powershell -NoProfile -ExecutionPolicy Bypass -File tools/setup.ps1 -Cuda` |
| 启动 | `npm start`，或 `node service/start.mjs` |
| 检查 | `npm run check`，或 `node tools/check.mjs` |
| 导入项目内合法角色文件 | `npm run avatar -- "assets/my-avatar.vrm"` |
| 校验笔记结构 | `node StudyVault/_tools/validate.mjs` |
| 单文件语法检查 | `node --check service/public_api.mjs` |

仓库没有 `test`、`build`、`lint` npm 脚本，也未发现独立测试套件或 CI 工作流。页面直接使用 ES Modules；`check` 的范围见 [[来源与验证]]。

## 环境变量和默认值 → [[中文意图与进程]]

| 变量 | 默认值 / 来源 | 作用 |
|---|---|---|
| `PORT` | 8769 | 本地网页服务 |
| `HAST_LLM_PORT` | 8783 | llama.cpp 本地服务，范围 1024–65535 |
| `HAST_MODEL` | `configs/qwen_intent.json` 的 `model` | GGUF 路径覆盖，SHA 校验值仍来自配置 |
| `HAST_LLAMA_SERVER` | 同配置的 `server` | 推理可执行文件路径覆盖，校验值仍来自配置 |
| `HAST_DEVICE` | 配置中当前为 `CPU` | 只接受 `CPU` / `CUDA0`；CPU 强制 GPU 层数为 0 |

## 故障定位 → [[易错点与复习]]

| 现象 | 先观察 | 继续阅读 |
|---|---|---|
| 计划请求 400 | 请求 Origin、Content-Type、generation、context 和错误正文 | [[HTTP接口]] |
| 第一条中文很慢 | `/v13-api/status` 的 `device`、`ready`、`busy`；冷启动与预热 | [[中文意图与进程]] |
| 回复到了，动作不对 | `lastPlan.intents` → `selections` → `tracks` → 求解报告 | [[指令执行链路]] |
| 动作后出现旧消息覆盖 | revision、AbortController、queue | [[页面与对话]] |
| 姿态失败后暂停 | held/rejected 帧、`requires_pause` 和硬约束 | [[姿态约束与求解]] |
| 角色加载失败 | VRM 完整骨骼、`avatarProfile`、动态 profile 路由 | [[角色骨架与旋转]] |
| 资源报错或形状不符 | SHA-256、骨骼顺序、registry、轨迹字节数 | [[模型资源与运行时]] |
| 面部某通道无效 | 模型实际 morph、注册与 available 集合 | [[面部表情]] |

## 浏览器调试 → [[页面与对话]]

```javascript
window.languageV13.state()
window.languageV13.dialogue()
window.languageV13.geometry()
window.languageV13.pause()
```

在页面完成初始化后使用。主页面加 `?debug=1` 可开启调试样式。`advance`、`send`、`reset` 也在该对象中，会改变运行状态；进行手动推进前先暂停自动播放。
