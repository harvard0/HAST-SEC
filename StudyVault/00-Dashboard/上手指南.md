# 上手指南

## 先准备什么

推荐 Windows 10/11、Node.js ≥22（包含 npm）和支持 WebGL 的现代浏览器。首次安装需要网络及约 2GB 可用空间，CUDA 路径需要更多空间。软件依赖与模型资源是两次独立安装。

所有命令在包含 `package.json` 的项目根目录执行：

```powershell
node --version
npm --version
npm ci
```

若 PowerShell 限制 `npm.ps1`，可使用 `npm.cmd`；若 npm 本身不存在，需要修复 Node/npm 安装与 PATH。单独能运行 node 并不等于已有 npm。

## 安装资源：选择一种

CPU：

```powershell
npm run setup
```

兼容 NVIDIA 显卡与驱动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/setup.ps1 -Cuda
```

安装脚本下载固定版本的 GGUF、llama.cpp 运行库及缺失的示例 VRM，并校验 SHA-256；同时更新 `configs/qwen_intent.json` 的 `device` 与 `gpu_layers`。见 [[安装配置与检查]]。

## 启动与最小体验

```powershell
npm run check
npm start
```

打开 `http://127.0.0.1:8769/language-lab`。页面初始暂停；点击“开始或继续”，输入“你好”，再单独输入“挥挥左手”。分别观察回复、角色自身左侧动作和实时曲线。点击“暂停”会停止回放并请求释放本服务拥有的语言推理进程。终端按 Ctrl+C 退出服务。

> [!tip] 先读再运行
> 学习代码不要求下载语言模型。`node tools/check.mjs` 可直接运行仓库检查；它检查语法、相对引用和仓库内运动资源，不要求真实语言模型推理成功。

## 遇到端口冲突

```powershell
$env:PORT = '8779'
$env:HAST_LLM_PORT = '8784'
npm start
```

前端端口默认 8769，语言服务默认 8783。修改只作用于当前 PowerShell 会话及随后启动的进程。

## 学习时怎样验证修改

| 修改范围 | 第一步 | 还需验证 |
|---|---|---|
| Node 或浏览器 `.mjs` | `node tools/check.mjs` | 与变更对应的接口或浏览器行为 |
| 意图提示词、槽位或计划 | 同上，阅读 [[HTTP接口]] | 真模型输出、计划含义和实际动作一致 |
| 求解或坐标 | 同上，阅读 [[姿态约束与求解]] | 可行性、连续运动、暂停与重置 |
| 学习库 Markdown | `node StudyVault/_tools/validate.mjs` | Obsidian 链接、表格与折叠显示 |

当前环境完成了什么见 [[来源与验证]]，不要把本页操作步骤当作已经执行的结果。
