## 练习 1 — 从进程到网页 [trace]

`npm start` 后访问 `/language-lab`，依次经过哪些文件？three 从哪里加载？

> [!answer]- 查看答案
> `package.json` 的 start → `service/start.mjs` → `publicServer` → `runtimeRoutes` 中 `/language-lab` 映射到 `web/v13_lab.html`。HTML importmap 将 three/three-vrm 指向 `/vendor/`，服务器再将 vendor 限定到对应 node_modules 目录。

## 练习 2 — 更换网页端口 [config]

需要在8779运行网页，是否还必须改语言服务端口？

> [!answer]- 查看答案
> 在启动进程前设 `$env:PORT='8779'`，然后 `npm start`。网页端口由 `service/start.mjs` 读取；语言端口由 `qwen_process.mjs` 的 HAST_LLM_PORT 读取，默认8783，两者独立。页面使用相对 URL，无需手动替换每个 fetch。

## 练习 3 — PowerShell 的 POST 为什么失败 [debug]

服务 GET 正常，但手写计划请求收到400，应检查哪些输入？

> [!answer]- 查看答案
> 查看 `service/public_api.mjs`：Origin 必须为当前 Host 的 HTTP 同源值，Content-Type 必须恰为 application/json；body 必须是对象且字段在白名单；plan 需 generation=v15、合法 text/context/session。再读 error 正文。若外层 Host/Origin 被拒绝会是403，不能全部当作模型错误。

## 练习 4 — 添加只读诊断接口 [extend]

想返回服务版本和已登记技能数，应放哪里、怎样验证？

> [!answer]- 查看答案
> 可在 `service/public_api.mjs` 明确登记 GET 路径，并基于已加载 manifest/library 返回少量元数据；同时检查 api 的路径识别入口，确保新路径真正进入分派。保留外层本机边界，避免返回本地绝对路径。建议补接口成功/方法错误检查，再在 HTTP 笔记记录。此处是扩展方案，当前无该接口。

## 练习 5 — 404与405不是同一层 [analysis]

POST 一个未知静态路径，与 POST `/v13-api/unknown`，为什么可能有不同状态？

> [!answer]- 查看答案
> API 先分派。`/v13-api/` 前缀被 `publicApi` 识别，但未知地址/方法抛错并返回400 JSON。非 API 请求继续走外层 GET/HEAD 限制，POST 因而返回405文本。GET 未映射资源通常404。应按实际分派顺序分析。
