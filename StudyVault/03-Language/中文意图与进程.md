# 中文意图与进程（核心度 ★★★）

## Purpose

将短中文上下文解析成已支持的语义槽位，编译成动作计划；对普通聊天生成回复和表现字段，并按需管理本地推理子进程。

## Key Files

| 文件 | 职责 |
|---|---|
| `qwen_process.mjs` | 读取配置、文件哈希、spawn、health 等待与 stop |
| `qwen_intent.mjs` | busy/owner、warm、plan、proactive、cancel、shutdown |
| `qwen_requests.mjs` | `/v1/chat/completions` 请求、schema、slot 与超时 |
| `qwen_contract.mjs` | 基础意图 schema、提示词和 few-shot 示例 |
| `qwen_parts.mjs` | 扩展 part、挥手与抬腿，强调当前消息 |
| `qwen_slots.mjs` | 模型槽位 → 可执行 key，不扫描用户原文 |
| `qwen_dialogue.mjs` | 对话 schema、表达枚举、解析与 emoji 装饰 |

表中文件均位于 `service/`。

## Public Interface

`qwenIntent(root, classes)` 返回 `state/stop/warm/shutdown/proactive/cancel/plan`；`qwenProcess(root)` 返回 endpoint、state、stop、settings、ensure。`compileSlots(plan,{parts})` 转换模型字段，`readDialogue(raw)` 验证表现字段。

## Internal Flow

```text
idle -> begin(owner, kind, AbortController) -> ensure process
  -> JSON intent (slot 0) -> compileSlots
       | command/release -> return
       + chat / v15 fallback -> dialogue (slot 1) -> readDialogue
  -> cool -> idle timer -> stop
```

计划请求 `temperature=.1`、max_tokens=650、60秒请求超时；对话请求 20秒超时，v15 使用结构化 schema。公共请求关闭 thinking，开启 prompt cache。warm 只用 max_tokens=1 建缓存，丢弃输出，不经过动作执行入口。

## 槽位与表现

| 字段 | 含义 | 易错处 |
|---|---|---|
| side | 角色自身左/右 | 不等于屏幕左右 |
| part | 手臂 / 腿 | 腿仅支持上抬，不能换成手臂 |
| action / height | 方向与高度分别预测 | 齐平头部与高于头顶不是同一动作 |
| 幅度 / 速度 | 编译为 strength / speed | 小幅与慢速分别控制 |
| delay | 相对本次请求起始时间 | timing 由不同 delay 推导 |
| presentation | expression、gesture、engagement | 由聊天模型额外产生，不是动作槽位 |

parts=true 时，缺 part 或不支持的腿动作会触发编译异常。当前 v15 调用方将编译异常转成 unsupported，再转换 chat；最终仍由 `validateResult` 检查结果。新增能力应同时考虑协议、编译、批准技能和客户端策略。

## 进程生命周期

`ensure()` 复用启动 Promise；首次启动校验模型和 server SHA，检查端口，再 spawn 本服务拥有的进程。health 轮询就绪后记录 startup_seconds。启动 ticket 识别取消；stop 清除状态并 kill 所有权范围内的 child。

共享 busy 防止同时处理多个计划。`cancel(session, release)` 在忙且 owner 不匹配时返回 false；stop 使用 release=true，interrupt=false。interrupt 会中止普通 plan，但保留 warm 的特殊处理；shutdown 标记 closing 并中断、停止和等待结算。

## Dependencies

使用 Node child_process、fetch/AbortController、llama.cpp GGUF 运行库；由 [[本地服务]] 与 [[HTTP接口]] 调用。输出交给 [[页面与对话]] 和 [[动作策略与轨道]]。

## Configuration

| 配置 | 当前值 / 来源 |
|---|---|
| model | `assets/models/Qwen3.5-0.8B-Q8_0.gguf` |
| server | `runtime/llama-server.exe` |
| device / gpu_layers | CPU / 0（安装 CUDA 会修改） |
| threads / idle_seconds | 6 / 120 |
| context / parallel | spawn 参数 8192 / 2 |
| 环境覆盖 | HAST_LLM_PORT、HAST_MODEL、HAST_LLAMA_SERVER、HAST_DEVICE |

threads 仅接受整数 1–32，设备仅 CPU/CUDA0。仅改模型路径不会同步修改 SHA 校验值。UI 固定“独立显卡”提示不能作为设备证据。

## Testing

运行 `node tools/check.mjs`；纯编译和结果校验可用手工构造对象检查。真模型测试需安装权重/运行库，用当前 API 发送原文，记录槽位、key 和实际动作。创建本库时未执行真实推理，也未验证 CUDA。
