# 系统架构

## 运行边界

```text
Windows / local machine
  Node HTTP service :8769 (127.0.0.1)
    |-- static modules, models, config, avatar ------> Browser
    |-- plan / proactive / warm / stop                 |
    |       |                                         | Three.js + three-vrm
    |       +--> qwenIntent --> owned llama-server     | policy + beatLayers
    |                          :8783                  | controllerV9 @ 20 Hz
    |                          /v1/chat/completions    | fixedClock + WebGL
    +<---------------- JSON plan -------------------->|
```

这是按进程和责任域分开的本地应用。仓库未出现数据库、远端业务 API、服务端渲染或打包构建管线。对话历史主要保存在浏览器 `commandLoop` 闭包，服务端模型状态在内存中。

## 启动与装配顺序

1. `service/start.mjs` 以模块路径计算项目根目录，调用 `publicServer`，注册 SIGINT/SIGTERM 关闭。
2. `publicServer` 先生成静态路由、技能库/API、资源采样器，再绑定 `127.0.0.1`。
3. `/language-lab` 返回 `web/v13_lab.html`。importmap 将 three 与 three-vrm 映射到本地 vendor 路径。
4. HTML 加载 `v15_start.mjs`（样式和页面标题）与 `v13_lab.mjs`（实际装配）。
5. `generation()` 返回 v15 选择；装配技能库、底座、历史模型、控制器、表情、策略、轨道、时钟和消息循环。
6. 初始化 `reset()` 后保持暂停，用户开始或聚焦输入框时按路径触发语言模型预热。

> [!important] 工厂参数比默认值更可靠
> `feasibleView` 默认使用旧 `feasibleController`，但当前主入口显式传入 `controllerV9`；`conditionalBase` 也收到 `/v15-data/`。脱离调用点只看默认值会读到另一条链路。

## 数据持有与生命周期

- 模型和动作文件持久保存在 `models/`，配置在 `configs/`；安装后新增本地资源在 `assets/`、`runtime/`。
- 浏览器维护短聊天上下文、最多六条等待消息、最近二十个求解姿态以及最近十五秒图表数据。
- Node 维护一个共享语言模型忙状态与 owner session，两个推理 slot 不代表同时处理两个 UI 任务。
- 暂停、页面隐藏或离开会走取消/释放链路；关闭服务调用模型 shutdown。
