# 数据与坐标契约

## 四种数据不要混淆

| 数据 | 形状 / 单位 | 谁解释 |
|---|---|---|
| 中文意图槽位 | side、part、action、height、幅度、速度、hold、delay | `compileSlots` |
| 编译计划 | key、strength、speed、hold、delay；base、operation | 浏览器命令循环 |
| 身体模型特征 | 53×3 旋转向量 + 19 表情 = **178**；20Hz | `beatFrame`、运行时 |
| 技能轨迹 | 每帧 53×4 Float32 四元数 = **848 字节** | `skillAssets`、`beatLayers` |

历史模型 `dim=181`，包含身体/表情与额外根通道，`lags=4`、20Hz；不要用它覆盖身体模型的 178 维假设。

## 公开动作交换格式

`motion/schema.mjs` 定义 `lumen-motion` v1：

| 属性 | 定义 |
|---|---|
| 坐标系 | 右手系，+Y 向上，+Z 向前 |
| 位置 / 时间 | 米 / 秒 |
| 四元数 | `xyzw`，归一化局部参考姿态增量 |
| root | 标准根参考的偏移，不能再次叠加同一位移 |
| bone_order | 角色自身解剖学左右；顺序决定通道含义 |
| frames | 声明通道的完整快照，按时间戳解释 |
| confidence / contacts | 可选，缺失或 null 表示未知 |

> [!important] schema 与实时内部格式的边界
> 公开交换格式最多声明 5 个独立口型通道；实时身体模型包含 19 个面部通道，v9 表情还可注册额外通道。三者不能当成完全相同的数组布局。

## 旋转与 VRM 适配

```text
model rotation vectors
  -> rotationExp -> canonical xyzw
  -> PoseController.adapt (VRM0 x/z sign conversion)
  -> poseState + fixed root reference
  -> solver / normalized bones
  -> syncAvatar -> raw VRM / scene
```

`PoseController.direction` 在 VRM0 为 -1，其他为 1；`adapt` 翻转 x/z 分量。每个边界已定义自己的转换，新增功能时应跟踪调用链，避免重复适配。显示结果进入选择器 history 时，主入口会转换回规范方向。

## 来源、哈希与顺序

素材 source 定义 id、file、frames、sha256；class 定义 key、mask、候选 skill；skill 指向 source 和帧区间。`registry_sha256` 用于关联登记版本，文件 SHA 用于核对内容，两者作用不同。

```text
manifest/classes -> key -> mask + skills
                               |
                             source id
                               |
sources shards -> file + frames + sha256 -> binary frames
```

浏览器要求轨迹字节数等于 `frames*53*16`、值有限、哈希相符；策略还检查骨骼顺序和登记关联。维数相同但骨骼顺序不同，仍是错误资源。
