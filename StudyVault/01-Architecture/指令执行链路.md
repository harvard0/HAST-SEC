# 指令执行链路

## 一条“挥挥左手”的路径

```text
form submit
  -> commandLoop.send(text)
  -> lowLatency.prepare() / POST warm
  -> POST /v13-api/plan {text, context, session, generation:'v15'}
  -> publicApi validates request
  -> qwenIntent.plan -> process.ensure -> extended.plan
  -> llama.cpp JSON intent -> compileSlots(parts:true)
  -> validateResult -> JSON response
  -> assets.load -> policy.select(entry, history)
  -> layers.add(selected.entry, parameters, pose)
  -> behavior.lock / behavior.apply
  -> play -> fixedClock -> step(0.05)
  -> behavior.sample -> beatFrame -> layers.sample
  -> view.render -> controllerV9.step -> final validation
  -> fixedClock.display -> view.display -> VRM / WebGL
```

1. 服务端根据 schema 和示例得到 `side=左`、`part=手臂`、`action=挥手` 等字段。
2. `compileSlots` 将其编译为 `left-挥手打招呼`，把幅度/速度转为 `strength`/`speed`，按 delay 排序。
3. 客户端加载已登记来源的轨迹并校验；v15 策略先询问 wave 分支，否则 expert，再否则旧策略。
4. 单个选中 skill 送进轨道，经过淡入、循环、保持与淡出，再与底座按 mask 混合。
5. 候选姿态经过约束求解与显示验证才写入角色；计划返回 200 不代表这些后续阶段已经成功。

## 分支与可观察结果

| 情况 | 当前行为 | 观察入口 |
|---|---|---|
| 普通 chat | 意图解析后再请求结构化对话 | `lastPlan.reply`、`presentation` |
| v15 command | `reply` 设为空，动作单独执行 | `intents`、`selections`、`tracks` |
| v15 unsupported / 空 command 且不改底座 | 改为 chat，并调用对话模型 | `operation`、对话内容 |
| release | 服务端无动作 intents；客户端 `layers.clear()` 淡出 | 轨道权重随时间降低 |
| 只改底座 | `base.change=true`，可无 intents | `behavior.state()` |
| chat 附带 gesture | 对话控制器额外选择问候挥手 | `presentation.gesture`、轨道 |

> [!warning] 对话可能触发身体动作
> `operation=chat` 且 intents 为空，仍可能因 `presentation.gesture` 进入挥手轨道。定位动作来源时要同时检查这两个路径。

## 排队、中断与失效结果

用户请求处理中可再排最多六条；主动对话处理中，用户输入会取消前端请求，并请求 `/v13-api/interrupt`。每次启动或取消改变 revision，异步结果只有 ticket 仍匹配时才继续。浏览器 AbortController 与服务端模型取消分别负责两端生命周期。

## 调试时保留哪些证据

将输入原文、HTTP 请求/响应、编译后的 key、选中 skill/source、轨道 mask/weight、solver 的 feasible/requires_pause 和可见角色动作放在同一条记录中。这样可区分语言理解、动作选择、轨道叠加、求解修正和角色适配问题。
