# 角色骨架与旋转（核心度 ★★★）

## Purpose

将统一姿态写入不同 VRM 角色，并提供旋转数学、角色加载、手臂目标和骨架净距补偿。理解 normalized/raw 骨骼、局部/世界坐标是修改动作的前提。

## Key Files

| 文件 | 作用 |
|---|---|
| `web/model_loader.mjs` | GLTFLoader + VRMLoaderPlugin、VRM0 预处理 |
| `web/feasible_view.mjs` | 动态 profile、角色、solver 和 viewer 装配 |
| `service/avatar_profile.mjs` | 从本地角色读取 VRM 版本和完整骨骼 |
| `motion/pose_controller.mjs` | 标准骨骼访问、方向适配、旋转/根/表情写入 |
| `motion/avatar_sync.mjs` | 角色同步边界 |
| `hands/arm_ik.mjs` | 两段手臂 IK，保留当前肘平面 |
| `hands/clearance.mjs` | normalized/raw 肩位置补偿与手部偏移工具 |
| `retarget/rotation_math.mjs` | rotationLog/Exp、delta、噪声与频谱辅助 |

## Public Interface

`modelLoader()`、`prepareModel(gltf)`；`PoseController` 提供 setRotation/getAngles/setRoot/setExpression/reset/capture/applyFrame/bindSampler；`armTargets(controller)` 返回 `(side,target,strength,elbowHint)`；`createClearance` 返回 shoulders/offset/hands。

## Internal Flow

```text
avatar.vrm -> GLTF/VRM load -> prepareModel
  + dynamic profile -> required bone checks
  -> PoseController / direction -> reset / floor alignment
  -> shoulder correction -> rig construction -> solver
  -> normalized pose -> syncAvatar -> raw skeleton -> WebGL
```

肩补偿发生在 solver 构建前，先恢复保存的 rest 位置，再沿角色左右轴移动 normalized 和 raw 肩；重复配置不会无限累加。当前主链路通过 createClearance 做肩校准，不能据工具有 `hands()` 就推断每帧都会调用独立 IK。

## 必要的数学

| 表示 | 用途 | 注意 |
|---|---|---|
| 四元数 `xyzw` | 旋转、slerp 混合 | q 与 -q 表示同一旋转 |
| rotationLog(q) | 单位旋转 → 三维旋转向量 | 先归一化并选 w≥0 的表示；接近零返回零向量 |
| rotationExp(v) | 旋转向量 → 单位四元数 | 模长为旋转弧度，方向为轴 |
| deltaRotation(a,b) | `log(a^-1 b)` | 乘法顺序决定参考系 |
| setRotation | 输入 XYZ 欧拉角，单位度 | 内部转为弧度和四元数 |

两段 IK 将目标距离限制在 `abs(l1-l2)+epsilon` 与 `l1+l2-epsilon`，避免不可达距离；肘提示决定弯曲平面，默认保留当前肘平面，退化时才用回退方向。它不等于完整人体碰撞求解，当前 v9 每帧几何任务主要在 [[姿态约束与求解]]。

## Dependencies

使用 three 与 three-vrm；被 [[页面与对话]]、[[姿态约束与求解]]、[[动作策略与轨道]]、[[面部表情]] 使用。动态 profile 由 [[本地服务]] 提供，骨骼顺序与 [[模型资源与运行时]] 配套。

## Configuration

`configs/skeleton_profile.json` 定义必需骨骼顺序；`configs/rig_profile.json` 定义骨架图；`configs/v9_control.json` 的 shoulder_offset_m 当前为0.02、hand_forward_m 为0.02、playback_torso_forward_degrees 为6。profile 路由返回值会根据实际 VRM 调整。

## Testing

运行 `node tools/check.mjs`。完整环境可用项目内合法 VRM 执行 `npm run avatar -- "assets/my-avatar.vrm"` 并刷新页面；检查左右、根位置、手指、眼睛与表情。导入器限制100MiB并要求完整 profile 骨骼，导入成功仍需观察动作适配。当前没有角色渲染验证。
